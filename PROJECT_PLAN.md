# Проект «Городская больница» — телефон + часы врача (Wear OS)

Этот файл хранит договорённости. Если чат оборвётся, загрузи архив проекта в новый чат и напиши
«продолжай по PROJECT_PLAN.md» — работа продолжится с первого невыполненного блока.

## Исходное задание
БД с ACID, CRUD, ORM; приложение в Android Studio, внесение данных. БД: hospital_sqlite.sql (Room, 13 таблиц).

## Что строим
Телефон (модуль app) — хранит расписание (Room), синхронизирует его с часами.
Часы (модуль wear, Wear OS, Compose) — основной упор на дизайн. Пользователь часов — ВРАЧ.
Все тестируется в эмуляторе (Wear OS + телефон с Google Play, сопряжение через Pairing Assistant).
Сборка APK — GitHub Actions (assembleDebug собирает оба модуля).

## Требования к часам
- Material Design для Wear OS: ScalingLazyColumn, AppCard / TitleCard, круглая карточка пациента.
- Очередь пациентов врача: статус (ожидается / опаздывает / пришёл / завершён), ФИО, год рождения,
  кабинет, причина визита, время записи, метки важного (напр. «Лейкоциты повышены»).
- Опоздание: пациент опаздывает, если не отмечен через 10 МИНУТ после времени записи.
  Тогда часы подают сигнал LATE_ALERT (тройная вибрация), карточка красная, счётчик «Опаздывают: N».
  На опаздывающем нижняя кнопка «Позвать следующего».
- Верхняя кнопка «Пришёл»: фиксирует время прихода (arrivedAt), пишет в БД (на телефоне) и меняет статус.
  Затем «Завершить».
- Микрожесты (имитация клавишами в эмуляторе): → двойной щипок = следующий пациент;
  ↓ одинарный щипок = сменить фокус; ↑ сжатие кулака = ОК (действие на выбранной кнопке).
- Режим «грязных рук» (по умолчанию ВКЛ): касания экрана часов игнорируются, работают только жесты.
- Вибрация: пресеты LIGHT / HEAVY / OFF отдельно для щипков и кулака; настройки на часах или с телефона;
  VibratorManager + VibrationEffect, подтверждение в Logcat (тег Haptic).
- Реальных микрожестов в Wear OS нет: слой GestureSource с заглушкой (клавиши), позже можно заменить
  распознаванием по гироскопу/акселерометру.
- Датчики необязательны (uses-feature required=false).
- Синхронизация: Wearable Data Layer, JSON-пакет расписания и настроек (телефон -> часы),
  событие прихода (часы -> телефон -> запись в Room).
- Отдельно (позже, по желанию): автономная версия «для телефона», где жесты имитируются кнопками
  и наклонами телефона.

## Решения и пожелания (добавлено позже)
- Для показа преподавателю достаточно: APK на телефоне, телефон Poco F7 (есть гироскоп), запись экрана эмуляторов,
  архив проекта. У Galaxy A12 гироскопа, скорее всего, нет, но есть акселерометр.
- ДОБАВИТЬ: экран врача на самом телефоне в стиле часов (кнопка «Пришёл» пишет arrivedAt в Room и видна на
  вкладке «Приёмы»), чтобы показать запись данных одним APK без часов. Предварительно блок 5b.
- Данные хранятся локально на устройстве (Room). Облако (общая БД, веб-страница просмотра) — возможное
  расширение после сдачи; сейчас не делать. Идея: очередь отправки, HTTPS, авторизация.
- Отчёт: после готового APK пользователь пришлёт образец титульного листа и отчёта; менять только ФИО,
  тему проекта и т.п.
- Пользователь присылает скриншоты ошибок (лучше Win+Shift+S). Объяснять простыми шагами «куда нажать».
- Формат работы: блоки по файлам, архив + PROJECT_PLAN.md, чтобы продолжать в другом чате.
